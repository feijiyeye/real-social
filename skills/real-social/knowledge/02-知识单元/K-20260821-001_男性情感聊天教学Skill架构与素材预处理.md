# 男性情感聊天教学 Skill 架构与素材预处理

## 核心内容

这套 Skill 的目标是按用户提供的专门化情感聊天体系进行教学，而不是收到聊天记录后无依据地直接代写回复。运行顺序固定为：收集可观察证据，识别当前阶段节点及可能的分链，说明置信度和缺失信息，提供体系内的可选回复方向；客户已选择方向并明确需要参考时，可生成示例话术；客户只说“直接帮我回复”但未选方向时，先引导其说清当下真实需求，再从已提供方向中选择最贴合的一条并生成示例。默认交付遵循阶段导航优先原则：先说明已完成什么、当前要解决什么、适用状态路由、允许的下一步、方向目的、反馈门槛和继续/切换/暂停条件，再决定是否进入示例。若有相似的已审核案例或标记为可召回的候选案例，展示案例的相似点、差异、结果和适用限制。

当前正式线上流程由[[K-20260826-001_真实社交线上流程推拉方向与回蓝闸门.md]]承载：兴趣证据收集阶段对外只提供 `push` / `pull` 两个主要战术方向，真实顾虑、条件调度、低回应、邀约窗口和停止边界走独立分流；保持真实恋爱/约会意图，普通话题朋友化漂移但双方仍互惠时自然回锚，不按固定回合数强转，对方明确只做朋友或无恋爱意向时停止回锚；只有“情绪表达平淡但仍持续互惠”才进入 `flat_but_engaged`，此时同等适用方向偏向轻度 push/假评，不把低回应、顾虑或不适当作无情绪；多 push、少 pull 是定性偏好而非固定比例，每次 push 预设可取消 pull，只有后续反馈主动、互惠且舒适时才释放；同一聊天关系中首次进入假性评估且适用条件成立时，第一方向固定为轻度 push，不允许先 pull 后 push，假评前普通真诚认可不计入该顺序，首推后的 pull 继续受反馈门控；对方的玩笑性挑战只有在持续互惠、舒适且无边界红灯时才可轻度推回，推后必须复核即时反馈，正向时下一轮优先拉；推拉目标是轻度张力与共同趣味，不是制造焦虑或情绪失衡；`push/pull` 战术层不得用解释、认错、服软、讨好或无条件让步换取认可、修复框架或逃避张力，事实错误、实际伤害、不适/拒绝、安全/同意问题和真实顾虑必须退出战术层进入责任、澄清、顾虑、条件或边界分流，必要真诚澄清、道歉和责任承担可以执行但不属于推拉；回蓝是跨阶段的恢复闸门，只提示状态，不检索或生成回蓝话术，也不授予重新联系许可。

素材处理采用分层架构：原始视频、音频、截图和文字先保真转写并保留来源；随后按语义片段抽取 `policy`、`stage`、`signal`、`rule`、`direction`、`case`、`boundary`、`viewpoint`、`conflict` 等候选知识单元；完成查重、价值筛选和冲突审计后，才由开发者裁决并晋级为当前有效知识。原始资料不是自动真源，不能仅凭出现次数或更新时间覆盖旧规则。

讲解型经典案例是本项目后续的主要案例来源。即使没有独立的原始聊天导出、完整说话人和消息时间，也要完整提炼讲解者的阶段判断、信号解释、操作目的、对方反馈、调整过程和案例结论，并与既有术语及体系化内容对齐。缺少原始聊天只影响直接事实验证，不阻断建立 `candidate case` 或从多个案例中累积候选结构。

## 运行协议

1. 输入阶段优先收集最近一段完整聊天、说话人、消息间隔、关系背景、目标和已知边界。
2. 区分 `observed`、`reported` 和 `inferred`，不把推测当成事实。
3. 输出当前阶段节点、最多三个候选节点及可能匹配的分链，并给出支持证据、反证和置信度；不假设存在唯一主链。
4. 证据不足、多个阶段冲突或命中未裁决规则时，暂停判断，只提出最少的澄清问题。
5. 阶段确认后，提供 2 至 4 个方向，说明目标、适用条件、代价和禁用条件，不默认给完整话术。
6. 客户已选择方向并要求参考答案时，或客户未选方向但已在引导下说明真实需求、由 AI 从 2 至 4 个方向中选定最贴合的一条后，才生成少量示例；已配置候选话术参考层时，按阶段与方向检索来源、回读上下文并经过边界过滤后再改写，不能随机抽句或机械粘贴。
7. 优先召回 1 至 3 个脱敏的经典案例；`candidate_callable` 案例可以作为候选参考召回，但必须标明候选状态、来源报告和限制，不能作为唯一规则依据。
8. 结尾标注调用的知识版本；命中冲突时显示冲突编号并等待开发者裁决。
9. 线上反馈调整按[[K-20260826-001_真实社交线上流程推拉方向与回蓝闸门.md]]执行；只有在战术层确实适用时才输出 `push` 或 `pull`。先检查恋爱意图是否发生朋友化漂移，再分离情绪表达与参与度；`flat_but_engaged` 且两个方向同等适用时优先 push/轻度假评，每次 push 同时记录待反馈的 pull 预案，不使用固定比例。首次进入假评操作且适用条件成立时，第一方向固定为 push，禁止先 pull 后 push；首推后仍先等反馈，再决定是否释放 pull。对方出现玩笑性推时，需先核对互惠与边界，再决定是否轻度推回；每次推后复核反馈，正向时优先拉，命中回蓝闸门时停止话术检索。不得在 `push/pull` 战术层用解释、认错、服软、讨好或无条件让步换取认可、修复框架或逃避张力；事实错误、伤害、不适/拒绝、安全/同意问题和真实顾虑退出战术层，必要真诚澄清、道歉和责任承担改走相应分流。
10. 阶段导航优先：每次收到新聊天证据，先显式区分 `observed`、`reported`、`inferred`，重新判断阶段节点和候选分链，并输出已完成事项、当前问题、状态路由、允许的 `push` / `pull` 或独立分流、方向目的、待观察反馈及继续/切换/暂停条件。术语只解释有证据支持的结构和转移条件，不直接当作话术模板；新反馈到达后必须重算阶段、方向和反馈门控，不能机械延续上一条建议。该条适用于聊天分析和回复任务，素材审计、入库与架构维护仍按各自输出。

## 素材筛选规则

对候选片段评估六项价值：是否影响阶段识别、是否影响下一步决策、是否可迁移、是否定义价值观/边界/例外、证据是否清楚、是否提供独特案例/反例/冲突。每项可用 0 至 2 分做初筛，但阶段、价值观、边界和冲突材料即使重复也保留来源关系。低价值内容先归档，不在第一轮物理删除。

完全重复或同义重复合并来源；适用范围不同则分开；互斥结论进入 `conflict`。讲师的经验判断、群体概括和激烈表达先进入 `viewpoint`，不能直接当成事实、`policy` 或 `rule`。新知识不能直接覆盖 `canonical`，必须经过 `candidate → review → canonical`，或进入待开发者裁决的冲突状态。

经典案例中的争议操作、激烈表达、性话题、心理归因和结果宣称不从案例中删除。原始资料层完整保留，案例层完整复原来源逻辑；再用 `source_preserved`、`candidate_callable`、`boundary_only`、`not_default_direction` 区分调用方式。既有排除裁决限制的是默认可调用规则，不是案例保存与体系研究；双方明确进入同类性话题后，符合条件的露骨表达可以进入候选参考，但不能绕过拒绝、停止、不适或安全边界。

体系常用话术同样采用“来源完整保留 + 调用状态分层”。原件和去重索引可以作为 `source_only_unreviewed` 检索源，人工首轮候选参考清单只提高 41 条表达的检索优先级，两者都不能因重复次数、章节名或讲师归类自动进入默认回复；客户未选方向时先完成需求对齐，再由 AI 从已提供方向中选择最匹配的一条。双方明确进入同类性话题后，相关露骨原句可按条件进入候选参考；具体调用协议、章节路由和高风险隔离见 `K-20260823-051` 至 `K-20260823-053`。

同一案例拆成多周目或多集时合并为一个 `case`，保留每个来源文件和章节定位，交界重复去重。阶段结构采用“阶段节点 + 多分链”：相同节点和转移条件合并，不同路径并存，不设唯一主链。具体执行口径见`04-系统/男性情感聊天讲解型经典案例处理规则.md`。

## 适用场景

- 整理视频、音频、截图、文字和真实聊天案例。
- 识别聊天阶段并进行体系化教学。
- 建立阶段规则、方向库、经典案例和版本冲突记录。
- 更新体系后运行回归案例，检查阶段识别、主动追问、方向输出和案例召回是否退化。

## 当前边界

本条仍主要保存架构与预处理方法，不承载具体来源话术。已由用户明确裁决的正式线上流程另见[[K-20260826-001_真实社交线上流程推拉方向与回蓝闸门.md]]；其他候选阶段、方向、案例和来源观点仍不能由 AI 自行补全或升级。`viewpoint` 只表示来源方的看法，不等于事实或本体系立场。第三方聊天资料需先脱敏；系统和开发者的更高优先级安全、隐私约束继续有效。
