# 体系话术库原句调用协议（候选）

## 核心内容

本批材料的定位是“真实社交知识库的话术库原句层”，不是新的正式规则库，也不是 AI 回复生成器。未来处理真实聊天时，继续使用固定顺序：

```text
可观察证据
-> 阶段节点与候选分链
-> 2-4 个回复方向
-> 客户选择方向并明确需要回复，或说明当下真实需求
-> 若未选方向，AI 从已提供方向中选择最贴合的一条并说明依据
-> 检索本批话术
-> 回读来源上下文并通过边界过滤
-> 在门槛满足时展示 1-2 条话术库原句
```

客户明确需要协助回复但未选方向时，不再要求其先做抽象的方向选择：先询问当下想达成的结果、希望的语气或最担心的问题；需求说清后，从已经给出的 2-4 个方向中选出最贴合的一条，再进入话术库原句检索。需求仍不清楚时不猜测、不随机套用。

## 检索与逐字展示

1. 先用阶段、方向、对方原消息和语气目标检索 41 条首轮候选清单及 Apple Notes 增补候选清单；没有合适内容时，再检索当前完整去重索引（2867 条唯一键），不做全库随机抽句。
2. 索引命中后，按 `archive_file + locator` 回读原件或文本提取的相邻段落。Markdown 情景对话尤其不能把单句脱离上下文使用。
3. 核对该条是对方消息、男方回复、情景标签、经验总结还是可发送表达。索引保留的是来源条目，不保证角色已结构化。
4. 逐字保留命中的话术库原句，不改写、拼接或适配成当前聊天的回复；补充与当前方向的相关点和不适用条件。
5. 通过[[K-20260823-053_体系话术高风险隔离边界候选.md]]过滤后，最多展示 1-2 条话术库原句；不满足门槛时不展示。

## 权限顺序

发生不一致时，按以下顺序处理：

1. 明确拒绝、停止、同意、隐私和安全边界；
2. 当前 `canonical` 运行架构和用户已裁决边界；
3. 已确认的阶段与需求对齐后确定的方向（用户选择，或 AI 根据用户需求代选）；
4. 本批来源话术。

原句与上层边界冲突时，舍弃或只保留为反例，不能以“这是体系常用话术”为理由覆盖边界。

## 去重含义

去重只解决同一句话在多个文件或章节重复出现的问题，不代表高频句更有效。标准化精确重复已合并来源；近似表达按 Dragon 的规则保留为并行变体并进入单独审计，防止不同对象或语境被误合并。

## 边界与例外

- 六份材料混合了可发送表达、对方原话、情景说明、经验主张、线下操作和高风险内容；“话术库原句”标签只说明它来自原版资料，不说明它适合当前关系或可以直接发送。
- 41 条首轮清单只是较高优先级的候选池，仍不是安全或效果白名单；`context_required` 和 `boundary_only` 必须按各自状态处理。
- Apple Notes 增补清单只提供 45 条代表性候选和 45 条章节路由；未列出的笔记条目仍保持 `source_only_unreviewed`，不能因笔记标题或重复出现而自动调用。
- `023_defusing_tests_and_body_language.md` 只有标题和媒体占位说明，附件未导出前不得从中推断肢体或线上回复内容。
- `source_only_unreviewed` 表示可检索、可复核，不表示可直接发送。
- 未来若多个候选句都不适合当前聊天，应明确不用，不为满足“参考”而硬套。
- 若用户选择的方向（或 AI 根据需求代选的方向）与现有来源没有合适表达，明确说明“本轮没有合适的话术库原句”，不自行组织或补写具体回复。
