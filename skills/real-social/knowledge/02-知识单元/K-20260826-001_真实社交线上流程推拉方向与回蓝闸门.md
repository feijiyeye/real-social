# 真实社交线上聊天流程：推拉方向与回蓝闸门

## 1. 定位与终点

本单元是 `K-20260821-001` 架构下的正式线上运行政策，适用于文字聊天中的反馈驱动调整。阶段目标不是单方面制造情绪，而是在不绕过拒绝、隐私、安全和反欺骗边界的前提下，确认双方兴趣、联系意愿和可执行的线下见面条件。

终点仍是“**双向兴趣与可执行见面**”；邀约入口仍是“**组合信号 + 直接邀约窗口**”。赋格可以作为观察项，但不使用固定数量作为门槛。

### 恋爱意图锚点

用户的目标是寻找恋爱/约会对象，而不是用“只想交朋友”掩饰真实目的。聊天可以进入日常、兴趣和普通信息交换，但这些内容应服务于认识彼此、判断吸引与适配、建立可执行见面，而不是无限停留在纯朋友式陪聊。

当普通话题持续一段互动、关系方向明显淡出，但双方仍持续主动提问或延展时，将下一步自然连接回个人偏好、互相吸引、关系判断或低压力约会方向。这里的“几轮后回归”是漂移检测，不是固定回合计数；若对方明确只愿意做朋友、没有恋爱意向或拒绝当前方向，停止回锚和 push，转入意图澄清或边界处理，不伪装接受友谊来等待突破。

## 2. 运行顺序

```text
完整聊天与背景
-> observed / reported / inferred 分离
-> 当前阶段与分链
-> 边界与安全核对
-> 回蓝闸门检查
-> 直接邀约窗口 / 顾虑与条件 / 低回应分流
-> 若仍适合战术调整，只显示 push 或 pull
-> 观察反馈并重新判断
```

“推”和“拉”只属于兴趣证据收集阶段的战术层，不是完整流程的全部动作。任何新的证据都可以让判断回到前一节点，但不能自动重启已经停止的推进。

### 阶段导航优先原则

本原则适用于聊天分析和回复任务；素材审计、入库和架构维护仍遵循各自的任务输出。真实社交任务的默认交付不是单独提供一句回复，而是先建立当前的阶段判断和行动方向。每次收到新的聊天证据后，必须先区分 `observed`、`reported` 与 `inferred`，识别当前阶段节点和候选分链，说明已经完成什么、当前要解决什么、适用哪条状态路由，以及下一步允许使用 `push`、`pull` 还是进入独立分流；同时说明本轮方向的目的、需要观察的反馈、何时继续、何时切换或暂停。体系术语用于解释阶段结构和转移条件，不能脱离证据套用，也不能把阶段名称直接当成话术模板。日常话题可以服务于激活、主题、调整、前提、恋爱意图回锚或邀约签约，但不得让用户只得到局部句子而失去对整体进程的判断。只有在阶段和方向已经明确、用户明确需要可发送内容且边界条件满足时，才补充少量示例；示例必须服从阶段导航，不得替代阶段识别、方向说明和反馈分流。收到新反馈后，应重新更新阶段、方向、反馈门控和下一步，而不是机械延续上一条建议。

## 3. 两个对外战术方向

### push

在对方仍持续参与、话题有互惠基础且没有不适信号时，轻度增加张力、筛选感、玩笑挑战或关系主题推进。推不能针对真实痛点，也不能依赖羞辱、威胁、欺骗、随机冷热或惩罚式消失。

### pull

给予认可、增加连接、降低距离；当强度偏高或反馈变淡时，降低强度、恢复舒适感、换普通线或留出空间。拉不等于连续追问，也不等于用奖励控制对方。

### 推拉组合逻辑

推拉组合不是对所有负反馈的反击，也不是固定的“推—拉”脚本。先判断对方的行为属于哪一种：

1. **玩笑性挑战或轻度反驳**：对方仍自愿参与，并继续提问、延展或接住互动。此时可以用轻度、对等但不必同强度的 `push` 回应，表达自己的真实偏好、判断或边界；“维持框架”指保持自身一致性和节奏，不指压过对方。
2. **真实顾虑、条件限制、低回应或安全信号**：不能推回。分别进入 `concern` / `condition`、`low_response`、安全或其他对应分流。
3. **明确拒绝、停止、删除或不要再联系**：直接进入 `stop_boundary`，不得再推，也不得用“测试”解释。

每次 `push` 后都要复核即时反馈。若对方仍主动、接住互动且没有不适，下一轮**优先**使用短 `pull`（认可、连接、降低距离或留出空间）来恢复温度；不要求同一条消息完成，也不把它当作机械必然的下一句。若反馈不明、变淡、回避或出现顾虑，停止追加 `push`，根据证据选择 `pull`、澄清、暂停或边界分流。

`push` 的目的限于轻度增加话题张力、表达真实立场并获得新的可观察反馈。推拉节奏可以在玩笑张力与真诚连接之间切换，但成功标准是双方持续、自愿、舒适且可退出的互动，不是焦虑、嫉妒、羞耻、不安全感或情绪失衡，更不是故意制造“情绪过山车”。

### 平淡但仍互惠时的 push 优先

“对方没有情绪”只能作为待核对的观察描述。只有同时满足以下条件，才标记为 `flat_but_engaged`：

- 对方仍持续回复，并有主动提问、信息补充、接梗或话题延展；
- 相比最近互动基线，情绪词、玩笑、调情、主动评价或明显情绪反应偏少；
- 没有疲劳、生病、忙碌、真实顾虑、不适、拒绝、安全或停止信号。

在 `flat_but_engaged` 下，若 push 与 pull 都适用，优先选择低强度 `push`，也可以使用语境明显、可逆且不触及真实痛点的玩笑性假性评估，以获得新的可观察情绪反馈。此处的目标是让互动出现可回应的轻度张力，不保证“制造出情绪”，也不把情绪强度本身当作成功。

若实际证据是连续低回应、没有主动延展或回复持续收缩，进入 `low_response`；若是现实顾虑、疲劳或不适，进入对应分流。两者都不能靠增加 push 处理。

### 首次假评起手顺序

“首次假评”指在同一聊天关系中第一次进入假性评估操作，不是整段聊天的第一句话，也不追溯假评前已经自然发生的真诚认可、礼貌回应或普通关系连接。只有当前仍处于 `interest_push_pull`、双方持续互惠、舒适且没有顾虑、低回应、不适、拒绝、安全或停止红灯时，才允许启动首次假评。

首次假评一旦启动，第一方向固定为低强度 `push`，不得先用 `pull` 铺垫再 `push`。该顺序约束只决定假评组合的起手方向，不要求在同一条消息中同时完成推和拉，也不保证第二步一定发送。

首个 `push` 发出后，必须先等待并核对即时反馈：只有反馈积极、对方继续主动互惠且舒适三项同时成立，后续短 `pull` 才进入 `ready`；反馈尚未出现或证据不全时保持等待；反馈含糊、变淡、转负，或出现顾虑、低回应、不适、拒绝、停止时，取消预案并进入对应分流。若首次假评的适用条件本身不成立，结果是暂不启动假评，不是改成以 `pull` 起手。

### 方向偏好与组合预案

当 `push` 和 `pull` 在当前语境中同等适用、且没有上一轮 push 的收束义务时，方向选择偏向 `push`。`pull` 少量使用，主要承担 push 后的短收束、真诚认可、关系连接或恢复舒适。该偏好不转换成固定比例、固定句数或连续 push 配额。

每次选择 push 时，都必须同时准备一个可取消的下一步 pull 预案，记录“打算如何拉回来”和释放条件。push 发出后：

1. 对方仍主动、接住互动且舒适：`planned_pull_status: ready`，下一步优先使用短 pull；
2. 反馈尚未出现：`planned_pull_status: pending_feedback`，不预发第二步；
3. 反馈不明、变淡、转负或出现顾虑：`planned_pull_status: blocked`，不机械发送预案，改走 pull、澄清、暂停或相应边界分流；
4. 明确拒绝、停止或删除：取消整个组合，不再推进。

`ready` 必须同时有积极反馈、继续互惠和舒适证据；只有笼统“正向”但参与度或舒适度不明时，仍保持 `pending_feedback`。运行字段中的 `tactical_direction` 记录当前实际允许的下一方向，而不是照抄用户请求；`pending_feedback` 或 `blocked` 时为 `null`，`ready` 时才可变为 `pull`。

### 不强行二选一

以下情况不归入推或拉，而是走内部状态分流：

- `clarify` / `concern`：澄清事实、真实顾虑、舒适感和关系预期；
- `condition`：核对时间、地点、交通、同行、方便与安全；
- `pause` / `low_response`：连续低投入时停止追问、减少投入或暂停；
- `direct_window` / `invite`：出现直接邀约窗口时进入低压力邀约；
- `topic_stop` / `overall_stop`：停止当前话题或整体互动；
- `unknown`：证据不足，暂不操作。

如果当前情形既不适合推也不适合拉，系统必须明确写“暂不操作，等待更多可观察证据”。

### 战术层禁止动作与责任例外

在 `push` 或 `pull` 被选为兴趣证据收集阶段的战术方向时，解释、认错、服软、讨好和无条件让步不能作为维持吸引、修复框架、换取认可或逃避张力的手段。这里的“禁止”只约束战术用途，不否认事实和责任。

如果确实存在事实错误、实际伤害、对方不适或拒绝、安全/隐私/同意问题，或对方提出需要认真处理的真实顾虑，立即退出 `push/pull` 战术层，转入 `clarify`、`concern`、`condition`、`privacy_safety_age_consent`、`topic_stop` 或 `overall_stop` 等分流。必要时应如实说明、承担责任、道歉或接受对方退出；这些动作不计为 `push` / `pull`，也不自动恢复旧的战术方向或重新联系许可。

`tactical_action_constraints`：

- `scope`: `interest_push_pull_only`
- `disallowed`: `over_explaining`、`defensive_justification`、`performative_apology`、`strategic_concession`、`appeasement_or_boundary_abandonment`
- `allowed_only_outside_tactical`: `truthful_clarification`、`genuine_apology`、`boundary_respecting_adjustment`
- `redirect_on`: 事实错误或伤害 -> `clarify`；明确不适或停止 -> `stop_boundary`；安全/同意/成年问题 -> `privacy_safety_age_consent`；物流或双方协商 -> `concern_condition`

## 4. 回蓝恢复闸门

### 定义

回蓝是操作者在持续消耗、推进无效或情绪开始影响判断时，暂停对外推进、收回投入并恢复状态的元节点。它不是女性兴趣阶段，不是第三种回复方向，不是反击动作，也不是重新联系许可。

### 触发

满足以下任一组合时，可以提示回蓝：

1. 连续多个回合低回应、无主动延展或没有新现实信息，且多轮投入没有改善；
2. 客户明确报告自己已经耗竭、焦虑、执着、想强行追回、反复证明自己或有施压冲动；
3. 多次澄清或条件协商仍无改变，继续投入只会扩大损耗。

单次慢回、表情、一次拒绝、一次改期、忙碌、生病或合理日程限制不能单独触发回蓝。

### 边界优先级

明确拒绝、停止、删除或“不要再联系”时，主状态必须是 `topic_stop` 或 `overall_stop`。此时最多把回蓝作为客户自身的恢复提示，不能改写为测试、隐藏同意或再次联系理由；运行字段同时固定为 `recovery_gate: blocked_by_stop_boundary`、`recovery_reason: explicit_stop_followup`、`recontact_permitted: false`。

真实顾虑和可调整的日程问题分别进入 `concern` 或 `condition`；仅有女生低回应而客户没有耗竭或施压风险时，先标记 `low_response`，不自动标记回蓝。

### 输出与退出

触发后只输出状态和停止推进说明：

```text
当前可以回蓝。
暂停主动推进并收回投入。
本次不提供回蓝话术，也不会自动重启或恢复旧许可。
```

运行时必须设置 `phrase_retrieval: disabled`。不读取、不展示、不改写来源中的“回蓝话术”。回蓝结束后，只有新的、自愿的、可观察的主动互动或具体现实条件出现，才重新做阶段判断；不使用固定等待天数，不继承旧邀约状态。

## 5. 正式硬边界

- 明确拒绝、不适、停止、删除和安全风险优先于所有战术方向。
- 不用推拉、回蓝、重启、冷冻或其他术语重新解释拒绝。
- 不把沉默、表情、点赞、长回复、语音消息或具体行程单独当作兴趣、同意或邀约许可。
- 不把来源中的侮辱、贬损、威胁、欺骗、随机冷热、控制和拒绝后施压内容转为默认回复。
- 性/亲密话题仍受既有成年、身份依据、持续互惠、退出条件和停止边界约束；本单元不降低这些标准。
