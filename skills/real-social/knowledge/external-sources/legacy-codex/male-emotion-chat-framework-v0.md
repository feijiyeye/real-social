# 男性情感聊天教学体系：素材预处理与 Skill 架构 V0

更新时间：2026-08-21

## 这份文件解决什么问题

目标不是让模型替客户“代回一句话”，而是让它成为一名按体系教学的教练：先判断聊天处于哪个阶段，再解释证据和不确定性，提供可选的行动方向；只有客户明确选定方向并要求参考答案时，才生成少量示例。

本 V0 先解决工程问题，不预先替开发者发明具体阶段、价值观或话术。

## 总体结构

```text
原始视频/音频/截图/文字
        ↓ 保真转写与来源登记
可追溯语义片段
        ↓ 分类、去重、价值筛选
候选知识单元
        ↓ 开发者审核与冲突裁决
当前有效体系知识
        ↓ 按阶段和适用范围检索
Skill：证据 → 阶段 → 方向 → 示例 → 案例
```

原始资料、候选知识和当前有效知识必须分开。原始转写是证据，不自动等于体系真源；“出现次数最多”或“最新出现”也不能自动决定权威。

## 知识层的最小分类

| 类型 | 作用 | 是否可直接指导用户 |
|---|---|---|
| `policy` | 价值观、优先级、不可违反的边界 | 只有开发者确认后 |
| `stage` | 阶段定义、进入/离开条件 | 只有 `canonical` |
| `signal` | 可观察的聊天信号 | 只有来源和边界清楚时 |
| `rule` | 条件、判断和适用范围 | 只有 `canonical` |
| `direction` | 回复的意图和策略方向 | 不等于完整话术 |
| `case` | 脱敏后的经典案例、过程和结果 | 作为教学参考，不作结果保证 |
| `boundary` | 反例、禁用条件和不适用场景 | 用于防止误用 |
| `viewpoint` | 来源方的经验判断、概括、立场或激烈表达 | 只能作为观点证据，不能自动当事实或规则 |
| `conflict` | 新旧互斥结论及待裁决事项 | 不得作为唯一答案 |

完整字段和示例见 Skill 内的 `references/knowledge-schema.md`。

## 素材处理流程

### 1. 保留原始证据

视频、音频、截图、聊天记录和文字原件只读保存。转写至少保留说话人、时间戳、转写不确定处；视频还要记录字幕、画面和明显语气信息。聊天记录先脱敏。

### 2. 按语义分段

以“一个完整判断、一个规则、一个案例、一个反例或一个边界”为单位切段，给每段分配 `source_id` 和 `segment_id`。不要只按固定字数切块。

### 3. 抽取候选单元

区分观察事实、观点、推测、规则、方向和示例句。来源方的经验判断、群体概括或激烈表达先抽成 `viewpoint`，每个候选单元都必须能回到原始文件的位置。没有证据位置的内容只能标为待补证。

`viewpoint` 不能直接升级为 `policy`、`rule` 或事实。只有在补齐可观察行为、触发条件、适用范围和开发者裁决后，才允许转化；否则保留原观点并标注“未经证实”或“仅代表来源方立场”。

### 4. 价值筛选

对每段按 0-2 分评估：

- 是否影响阶段识别；
- 是否影响下一步决策；
- 是否能迁移到多个类似案例；
- 是否定义价值观、边界或例外；
- 证据是否清楚；
- 是否提供独特案例、反例或冲突。

阶段、价值观、边界和冲突即使重复，也保留来源关系。低价值内容归档，不在第一轮直接删除。

### 5. 去重和冲突

- 完全重复或同义重复：合并来源，不制造多个规则。
- 主题相近但适用范围不同：分开保存，建立关系。
- 对同一阶段、同一条件给出互斥结论：建立 `conflict`，保留双方。

开发者只能在明确看到冲突后选择：保留旧规则、采用新规则、按场景拆分或两条并存。裁决后才把单元标为 `canonical`。

## Skill 运行协议

1. 收集最近一段完整聊天、时间间隔、关系背景、目标和边界。
2. 只陈述可观察证据；把报告内容和模型推测分开。
3. 输出一个主阶段或最多三个候选阶段、置信度、支持证据和反证。
4. 证据不足、规则冲突或知识未配置时，暂停判断并追问，不给方向。
5. 阶段确认后，给 2-4 个方向，说明目标、适用条件、代价和禁用条件。
6. 只有用户明确选定方向并索要参考答案时，才给示例句。
7. 召回 1-3 个相似经典案例，并说明相似点、差异、结果和限制。
8. 在结尾标记调用的知识版本；命中冲突时显示冲突编号和待裁决状态。

## 版本状态

```text
raw → normalized → candidate → review → canonical
                                  ↘ conflict
```

新素材不直接覆盖旧的 `canonical`。每次裁决后要记录来源、变更原因、影响的阶段/规则和需要重跑的回归案例。

## V0 的验证门槛

先用 3-5 份跨格式素材验证抽取口径，再用 10-20 条聊天案例验证：

- 清晰案例能否识别到正确阶段；
- 模糊案例是否主动停下来追问；
- 默认是否只给方向、不代答；
- 相似案例是否真正相似；
- 新旧矛盾是否完整暴露；
- 每条正式结论能否回到来源。

连续两批处理后不再修改字段、关系和去重规则，才扩大到批量素材。

## 当前使用方式

Skill 的运行协议在 `male-emotion-chat-coach/SKILL.md`；详细规则在其 `references/`；实际阶段、规则和案例以后放入独立 `knowledge/`，并把已审核单元标为 `canonical`。运行 `scripts/validate_knowledge.py knowledge` 做结构检查。

当前 V0 没有虚构任何具体阶段或价值观，因此第一次调用会在知识尚未配置时提示“体系未配置完整”，这是预期行为。
