## 四、案例一：杰哥2长周期邀约调度

### 候选分链

```text
激活/前提
  -> 主题/邀约
  -> 初次具体时间
  -> 有理由改期
  -> 暂停与长间隔
  -> 新证据重启
  -> 详细行程确认
  -> 当日调度/签约候选
```

### 六层提炼

- `source_dialogue`：字幕转述线下初识后加微信、初次问候、可用时间、饮品邀约、改期、远期日期、语音消息、未回城、疲劳、出差、周末替代安排、迟到和地点确认等片段；完整双方原始消息未独立提供。
- `source_interpretation`：讲解者把较快联系、中性回复、问号、改期理由、长间隔和详细行程解释为熟悉度、窗口、诚意、坚持或真实答应；这些解释保留为来源判断，不改写成事实。
- `source_move`：来源采用初次激活、直接试探邀约、接受改期、暂停追加、间隔后轻量重启、语音消息邀约和详细行程调度。语音消息是发送形式，不等于对方同意电话接听。
- `source_feedback`：材料报告对方给出具体日期、提前说明冲突并提出替代时间，之后又说明疲劳、出差、收拾行程并提出周末，临近见面时继续提供迟到和地点信息。
- `source_principle`：来源强调有理由的改期与模糊拖延不同；安排未成时接受暂停，只有出现新互动证据才重启；具体顾虑和替代方案比单个积极词更能支持调度判断。长等待本身不构成规则。
- `source_outcome`：来源报告数月后完成当日调度并见面；没有独立聊天导出、现场证据、见面质量或后续关系结果，结果状态为 `source_reported`。

### 调用限制

该案可作为 `candidate_callable` 相似案例召回，帮助识别“有理由改期 -> 暂停 -> 新证据重启 -> 详细调度”的候选路径；不能把固定等待时长、坚持、沉默、表情、单项位置询问或来源报告的到达变成正式规则或同意证明。

## 五、案例二：杰哥3即时安全调度

### 候选分链

```text
激活
  -> 同频道/舒适调整
  -> 主题/邀约
  -> 形式与安全条件调整
  -> 当日调度
  -> 签约/到达候选
```

### 六层提炼

- `source_dialogue`：字幕转述地铁口初识、立即加微信、紧张和被关注、自我评价、外表/内在标准、现实邀约、不喝酒、咖啡替代、疲劳、休息、地点变化、迟到和到门口等片段。
- `source_interpretation`：讲解者把同理心解释为进入同频道，把自我评价解释为测试或焦虑，把照片和标准解释为情绪起伏或窗口；外貌、性取向和服从度等归因没有独立证据，保留在来源层。
- `source_move`：来源先承接对方已表达的紧张，再交换个人标准并进入邀约；对方说不喝酒时改为低负担、公开场所的替代安排；对方疲劳或改变地点时先调整再继续核对条件。
- `source_feedback`：材料报告对方持续回应、提出形式限制、说明疲劳、继续给出出门时间和地点信息，最后在门口汇合；这些因果意义仍属于讲解者叙述。
- `source_principle`：来源强调先处理明确说出的不适和限制，再推进现实主题；连续互动后不必无限堆叠文字；形式变化、休息和地点变化应进入调度变量，而不是自动解释为拒绝或更高层意图。
- `source_outcome`：来源报告当日完成调度并到达；没有独立原始聊天、现场证据或后续关系质量，结果状态为 `source_reported`。

### 调用限制

该案可作为 `candidate_callable` 相似案例召回，帮助识别“连续互动 -> 直接邀约 -> 形式/疲劳条件调整 -> 当日调度”的候选路径；不能把“马上”“可以”、定位、到门口、照片或来源的外貌/服从度解释当作兴趣、同意或关系升级证明。

## 八、待验证问题

1. “具体改期原因 + 替代安排”在更多失败案例中能否稳定区别日程管理、礼貌拖延和继续调度意愿？
2. “长间隔重启”与用户术语中的暂停、断裂期或普通低回应应如何进一步区分？
3. “先承接不适再即时邀约”是否跨不同关系背景稳定，还是杰哥3的特定叙事路径？
4. 不喝酒、疲劳、地点变化等条件应统一归入形式调整，还是拆成安全、体力和日程三个维度？
5. 具体行程信号如何与已有赋格、远程反馈和低回应信号组合，才能避免过度解释？

## 九、下一步建议

继续收集不同结果、不同关系背景的讲解型案例，优先补充：明确未成的邀约、详细行程但最终取消的案例、没有长间隔重启的案例，以及文字转电话前有明确许可记录的案例。累计 10-20 条脱敏真实聊天或可核验案例后，再对阶段节点、分链转移、调度信号和方向候选做第一次开发者审核。
