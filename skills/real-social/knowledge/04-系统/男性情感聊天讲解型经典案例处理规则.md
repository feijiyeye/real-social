# 男性情感聊天讲解型经典案例处理规则

生效日期：2026-08-22

## 来源前提

用户已明确：后续经典案例主要以课程讲解、逐句复盘、代聊分析等形式提供，通常没有独立的原始聊天导出、完整时间戳或当事人自述。该来源形态是本项目的常态，不再作为阻断处理或反复补问的缺陷。

讲解型案例可以用于提炼体系逻辑、补充阶段结构、校准信号解释、建立方向映射和积累经典案例。缺少原始聊天只影响“能否当作独立事实验证”，不影响其作为来源体系证据的价值。

## 六层证据

每份讲解型案例按六层拆解：

1. `source_dialogue`：讲解者引用或转述的聊天内容；
2. `source_interpretation`：讲解者对窗口、兴趣、意图、阶段、关系位置或心理的判断；
3. `source_move`：案例使用了什么操作，目的是什么；
4. `source_feedback`：材料报告的对方回应、关系变化和下一步调整；
5. `source_principle`：讲解者由案例总结出的通用逻辑；
6. `source_outcome`：材料报告的邀约、见面或其他结果。

不能因为某一层属于来源解释，就从案例中删除。知识层应明确标注来源性质，再与既有体系术语和候选单元建立关系。

## 核心抽取单位

不要只摘聊天原句，也不要只做风险审计。优先抽取完整推理链：

```text
背景或阶段
-> 触发信息
-> 讲解者如何解释
-> 使用了什么动作及目的
-> 对方出现什么反馈
-> 为什么继续、调整或撤回
-> 讲解者总结了什么原则
```

同一逻辑如果只出现于一个案例，先保留在 `case` 或 `viewpoint`；多个独立案例反复出现后，可补成 `stage`、`signal`、`rule` 或 `direction` 候选。所有新内容仍保持 `candidate`，不自动成为 `canonical`。

## 原汁原味与调用分层

案例中的激烈表达、性话题、心理归因、反复联系、争议操作和结果宣称都保留：

- 原始文件完整归档，不改写原文；
- 案例单元完整复原来源逻辑，不因不适合默认推荐而删段；
- 原句可作为 `source_quote` 定位，但不自动进入默认回复生成；
- 用调用状态区分用途，而不是用删除解决问题。

调用状态：

| 状态 | 含义 |
| --- | --- |
| `source_preserved` | 来源内容完整保留，可用于理解体系和复盘案例 |
| `candidate_callable` | 已拆出条件、目的、反馈和退出条件，可参与候选方向判断 |
| `boundary_only` | 主要用于说明边界、失败或冲突，不作为正向方向 |
| `not_default_direction` | 可以研究和比较，但不能默认推荐给用户 |

“保留”与“默认推荐”是两个独立判断。既有 C 类裁决只限制其进入默认可调用规则，不再用于删除经典案例中的来源逻辑。

`candidate_callable` 的讲解型案例可以在用户提供相似聊天时被召回，作为候选参考展示相似点、差异、来源逻辑和限制；它不表示其中的操作已经成为正式规则。默认方向仍需经过 `canonical` 阶段、规则和边界过滤。

## 多周目合并

同一案例拆成一周目、二周目、三周目或多集时：

1. 合并为同一个 `case` 单元；
2. 每个周目单独归档并保留哈希；
3. 章节交界重复只去重，不另建案例；
4. 用完整时间线记录阶段变化、讲解逻辑和最终结果；
5. 后续周目补足结果时，更新原案例版本，不新增平行案例。

## 阶段链与分链

本项目不设唯一的阶段主链。每个案例可以贡献一条或多条 `chain_id` 分链；阶段节点和可观察转移条件是可复用的底层结构。后续案例出现相同节点或相同转移条件时合并，出现不同顺序、不同触发条件或不同中间节点时并行保留，不能用第一条成功案例覆盖其他路径。

## 与用户运行目标的关系

案例学习最终服务于两个目标：

1. 根据用户提供的聊天信息识别当前阶段节点及可能的分链，并说明依据与不确定性；
2. 阶段确定后只提供方向，不直接代答；用户明确选择方向且仍需要帮助时，才给少量参考答案。

阶段确认采用“当前节点 + 候选分链”输出，不把某一案例的路径写成全体系唯一主链。

案例中的现成话术不是默认答案库。需要学习的是讲解者为何在某个阶段使用某个方向，以及对方反馈后为何继续、调整或退出。
