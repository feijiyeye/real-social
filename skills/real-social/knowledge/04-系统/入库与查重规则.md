# 入库与查重规则

这套流程的目标是让用户只负责提供信息，AI负责判断它是否值得保存、应该怎样保存，以及是否已经存在。

## 一、先判断输入状态

收到材料后，先判断：

- 是需要保留原貌的长文、截图、转写或附件；
- 是可以直接形成知识单元的观点、经验、方法、事实或问题；
- 是暂时缺少语境、无法可靠判断的碎片；
- 只是当前讨论，不需要入库。

处理方式：

- 需要保留原貌：保存到 `01-原始资料/`，再判断是否抽取知识单元。
- 可以直接沉淀：进入查重流程。
- 暂时无法判断：保存到 `00-收件箱/`，标明缺少什么。
- 不需要入库：不写文件。

短小的用户原创表达可以直接写入知识单元的“来源与依据”，不额外复制一份原始文件。

## 二、写入前查重

查重范围：

- `02-知识单元/`
- `03-动态索引/`

默认排除：

- `00-收件箱/`
- `.trash/`
- `/Users/company/Documents/AI workspace`

至少检查：

1. 标题和别名是否相同。
2. 核心主张是否相同。
3. 关键词或主题是否高度重合。
4. 适用场景和边界是否相同。
5. 新材料是否只是为旧结论增加一个来源或例子。

## 三、六种处理结论

| 结论 | 判断标准 | 动作 |
| --- | --- | --- |
| 完全重复 | 内容和来源都没有新增价值 | 不新建，只记入库日志 |
| 同义重复 | 表达不同，实际主张相同 | 合并到权威知识，补充别名 |
| 补充 | 主张相同，但有新证据、边界或例子 | 更新权威知识并注明新增来源 |
| 近似 | 主题相近，但结论或适用范围不同 | 分开保存并建立关系 |
| 冲突 | 对同一问题给出互不兼容的结论 | 双方保留，标注冲突和来源 |
| 全新 | 没有可复用的现有知识 | 创建新知识单元 |

完全重复、同义重复和补充，默认不创建第二份知识文件。

## 四、知识单元格式

文件名：`K-YYYYMMDD-NNN_简明标题.md`

```markdown
---
id: K-YYYYMMDD-NNN
type: stage
title: 简明标题
created: YYYY-MM-DD
updated: YYYY-MM-DD
status: candidate
canonical: false
version: 1
topics: []
aliases: []
source_refs: []
related: []
---

# 简明标题

## 核心内容

用完整、明确的话写出这条知识到底说了什么。

## 适用场景

说明什么时候值得调用。

## 边界与例外

说明什么时候不适用；暂时不清楚就写“待验证”。

## 来源与依据

保留来源、日期和必要原文。区分用户观点、外部材料和 AI 推断。

## 关联知识

使用 `[[文件名]]` 链接相关知识，并说明关系。

## 变更记录

- YYYY-MM-DD：创建。
```

新建知识单元必须使用当前字段模板并从 `candidate` 开始。旧版 `active + canonical: true` 只对 `04-系统/知识单元元数据兼容清单.json` 中登记的历史文件有效，不得复制到新文件。

## 五、动态主题规则

- 每条知识自动生成 1 到 3 个主题词，不要求用户选择。
- 优先使用 `03-动态索引/主题索引.md` 中已有名称。
- 新词先作为候选主题，不立刻新建文件夹。
- 同义主题统一到一个主名称，其他写入别名。
- 同一知识可以属于多个主题。
- 只有达到建图条件时才新建主题地图。

## 六、日志更新

每次处理完成后：

1. 在 `04-系统/入库日志.md` 追加一行。
2. 发生合并、替代或冲突时，在 `04-系统/合并日志.md` 追加记录。
3. 更新 `04-系统/系统状态.md` 中的数量和最近处理时间。
4. 如主题发生变化，更新 `03-动态索引/主题索引.md`。

## 七、返回给用户

入库后简洁说明：

- 处理结果：新建 / 合并 / 补充 / 仅关联 / 待判断 / 未保存
- 保存位置
- 查重结论
- 自动识别的主题
- 关联的已有知识
- 是否需要用户补充一个关键信息
