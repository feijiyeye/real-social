# 检索与调用规则

知识库的价值不在于存了多少，而在于回答和行动时能否真正调用。

## 一、什么时候检索

默认规则：当前工作区中提出一个有实质内容的问题时，先检索 Dragon 知识库，再决定回答是否需要引用。用户不需要额外说“帮我查一下”。

以下情况必须先检索并明确引用：

- 用户说“根据我的知识库、结合我以前的内容、按我之前的观点”。
- 用户问到 `03-动态索引/主题索引.md` 中的活跃主题。
- 用户要写内容、做决策、复盘或制定方案，而库中可能已有相关经验。
- 用户担心重复劳动，询问以前是否做过类似内容。

以下情况可以不检索：普通闲聊、一次性事实查询、纯工具操作或明显与知识库无关的任务。

## 二、检索顺序

1. 读取 `SOURCE_OF_TRUTH.md`，确认有效范围。
2. 读取 `03-动态索引/主题索引.md`，寻找主题和别名。
3. 搜索 `02-知识单元/` 的标题、别名、主题和正文。
4. 打开最相关的少量知识单元。
5. 需要核实来源时再打开 `01-原始资料/`。
6. 检查相关知识是否存在冲突、旧版本或适用边界。

不要把 `.trash/`、`00-收件箱/` 或旧目录 `/Users/company/Documents/AI workspace` 当作当前知识来源。

## 三、如何回答

回答时区分三层：

- `知识库已有`：能够在本地文件中找到依据。
- `基于已有知识推导`：由现有内容合理推出，但原文没有直接写出。
- `AI 本次补充`：来自通用知识或当前推理，不代表用户原有观点。

当这一区分会影响判断时，要明确说清楚。引用已有知识时，提供对应本地文件路径。

## 四、找不到时

- 直接说明当前知识库没有相关记录。
- 可以继续给出 AI 的建议，但必须标明这是本次补充。
- 如果本次讨论产生了值得长期复用的新结论，完成任务后询问或根据用户明确意图执行入库。

## 五、避免重复造轮子

开始以下任务前，先查是否已有相近成果：

- 新建方法、模板、清单或流程；
- 写与过去主题相近的内容；
- 对同一问题重新做分析；
- 新建主题或标签；
- 创建与现有知识高度相似的文件。

如果已有内容能够复用，优先引用、更新或组合；只有旧内容确实不能满足新目标时才新建。

## 六、男性情感聊天话术参考层

当客户明确需要协助回复时，先按男性情感聊天项目的运行契约完成阶段导航，再决定是否检索话术。每次收到新证据，先区分 `observed`、`reported`、`inferred`，输出已完成事项、当前问题、阶段节点/候选分链、状态路由、允许方向、方向目的和反馈门槛；客户已选方向时沿用该方向，客户只说“直接帮我回复”但未选方向时，先用最少问题引导其说明当下真实需求，再从已经提供的 2-4 个方向中选择最贴合的一条并说明依据。只有阶段与方向明确、用户明确要求可发送内容且边界满足时，才进入示例门槛：

1. 读取 `K-20260823-051` 至 `K-20260823-053` 的调用协议、章节映射和风险边界。
2. 先按当前阶段、用户选定方向、对方原消息和语气目标查询 `01-原始资料/2026-08-23_Jackson体系话术候选参考清单.json` 与 `01-原始资料/2026-08-23_AppleNotesQuickNotes候选参考增补清单.json`；没有合适条目时，再查询完整的 `01-原始资料/2026-08-23_Jackson体系话术去重索引.json`（当前 2867 个唯一键），不要一次性载入全部索引。
3. 命中条目后根据 `archive_file`、`locator` 和 `section` 回读原件或稳定文本的相邻上下文，确认说话人和用途。`023_defusing_tests_and_body_language.md` 为媒体-only，在附件导出和复核前不产生任何话术或肢体操作结论。
4. 通过拒绝/停止、欺骗、施压和线上范围过滤后，按当前真实聊天改写少量示例；露骨性话术只有在双方明确进入同类性话题、成年/身份风险已有足够依据、存在持续互惠反馈且无拒绝或不适时，才可作为候选参考，仍需逐句回读和退出条件检查。

索引中的 `source_only_unreviewed` 只表示来源可追溯，不代表可直接发送。重复次数、章节名和来源强度均不能替代阶段判断或边界审计。

收到新反馈后必须重新评估阶段、方向、反馈门控和下一步；示例服从阶段导航，不能替代阶段识别、方向说明或独立分流。术语只能解释有证据支持的结构与转移条件，不能直接当作话术模板。

## 七、正式推拉战术层边界

在 `push/pull` 战术层，不得用解释、认错、服软、讨好或无条件让步换取认可、修复框架或逃避张力。若出现事实错误、实际伤害、不适/拒绝、安全或同意问题、真实顾虑或条件限制，必须退出战术层，分别进入责任/澄清、顾虑/条件或边界分流；必要的真诚澄清、道歉、责任承担和尊重边界可以执行，但不计为 `push` 或 `pull`。该边界与正式流程单元 `K-20260826-001` 的推拉组合规则一致。

回复方向还必须检查四个正式字段：

1. `romantic_intent_anchor`：保持真实恋爱/约会意图；普通话题朋友化漂移且双方仍互惠时自然回锚，不按固定回合数强转。明确只做朋友或无恋爱意向时停止回锚，进入意图澄清或边界处理。
2. `affect_engagement_policy`：只有情绪表达平淡但持续回复、主动提问或延展仍在时，才标记 `flat_but_engaged` 并优先轻度 push/玩笑性假评；连续低回应、顾虑、疲劳、不适和停止不能走该策略。
3. `direction_bias` / `planned_pull`：push 与 pull 同等适用时偏向 push，但不设固定比例、不连续加推；每次 push 同时准备可取消 pull，只有推后反馈主动、互惠且舒适时才释放。
4. `initial_false_evaluation_order`：同一聊天关系中首次进入假性评估且仍满足兴趣证据收集、互惠、舒适和无红灯条件时，组合内部必须以轻度 push 起手，不得先 pull 后 push。假评前的普通真诚认可不计入该顺序；首推后的 pull 仍须通过积极、互惠、舒适反馈门控，push 不适用时暂不启动假评。
