# 素材预处理管线

## 1. 保留证据

原视频、音频、截图和文字只读保存；转写保留说话人、时间戳、转写置信度、画面文字、停顿和不确定标记。不要用摘要替代原文。

### 讲解型经典案例

当用户明确说明后续材料主要是讲师复盘、课程解说或代聊讲解，而非原始聊天导出时，把这类材料视为可用于体系建设的正式来源类型，不因缺少原始截图、完整说话人或消息时间而停止抽取。

完整保留原文，并把内容拆成六层：

1. `source_dialogue`：讲解中引用或转述的聊天内容；
2. `source_interpretation`：讲解者对信号、心理、阶段和关系位置的解释；
3. `source_move`：讲解者使用或点评的操作及目的；
4. `source_feedback`：材料中报告的对方反应和关系变化；
5. `source_principle`：讲解者从案例提炼的通用逻辑；
6. `source_outcome`：材料报告的邀约、见面或其他结果。

缺少原始聊天只降低直接观察证据的等级，不降低讲解逻辑本身作为 `source_only` 体系证据的价值。来源方的判断可以用于建立候选阶段、信号、规则和方向，但必须注明它是来源解释，等待更多案例或用户裁决后再晋级。

## 2. 语义分段

按完整的判断、规则、案例、反例或边界分段。每段都带 `source_id` 和 `segment_id`，避免同一段话在不同版本中失去来源。

同一案例被拆成多周目、多集或多份解说时，默认合并为一个 `case`，按章节保留来源定位；章节交界的重复只做去重，不另建案例。

阶段结构采用“阶段节点 + 多分链”而不是唯一主链。抽取案例时分别记录可复用的阶段节点、节点之间的转移条件和本案例的 `chain_id`；相同节点或相同转移条件在不同案例中合并，不同顺序、不同触发条件或不同中间节点保留为并行分链。

## 3. 候选抽取

把段落拆成 `policy`、`stage`、`signal`、`rule`、`direction`、`case`、`boundary`、`viewpoint`、`conflict`。把观察事实、来源观点、推测、策略和示例句分开，不把讲师口头禅直接升级为规则。

讲师对“某类女性/男性”的概括、经验判断或激烈评价，默认先进入 `viewpoint`。若要转成 `signal` 或 `rule`，必须进一步拆出可观察行为、触发条件、适用边界和来源证据；无法拆解时保留为观点，不作模型的事实陈述。

对经典案例，优先抽取完整的推理链：`背景/阶段 -> 触发信息 -> 来源解释 -> 使用动作 -> 对方反馈 -> 下一步调整 -> 来源结论`，再与已保存的专业术语、阶段和方向对齐。不要只摘聊天原句，也不要只做风险审计。

案例中的激烈表达、争议操作、性话题、反复联系、心理归因和结果宣称都保留在原始资料和案例逻辑中，不因不适合默认推荐而删除。另设“调用状态”区分：`source_preserved`、`candidate_callable`、`boundary_only`、`not_default_direction`。保留内容与推荐内容是两个判断。

`candidate_callable` 对讲解型案例表示“可以在相似场景中作为候选案例参考召回”，不表示其中的操作已经成为正式规则；运行时必须同时显示候选状态、来源性质和结果状态，并继续用 canonical 边界过滤默认方向。

## 4. 价值筛选

用 0-2 分评估阶段辨识影响、决策影响、可迁移性、证据强度、独特性和边界/冲突价值。阶段、价值观、边界和冲突材料即使重复，也保留来源关系；低分材料归档而不是删除。

## 5. 去重与冲突

完全重复或同义重复合并来源；适用范围不同则分开；互斥结论进入 `conflict`，禁止用出现频率或日期自动决定权威。

阶段链之间的差异不自动视为冲突。只有对同一阶段、同一触发条件和同一目标给出互斥判断时，才建立 `conflict`；不同路径可以并行存在。

单个讲解型案例可以补齐候选结构，但不能仅凭一次成功叙事自动升为普遍规则。相同逻辑在多个独立案例重复出现，或用户明确裁决后，再考虑从 `case/viewpoint` 晋级为 `stage/signal/rule/direction`。

## 6. 样本闸门

先处理 3-5 份跨格式样本，再用 10-20 条聊天案例检查阶段识别、主动弃答、方向数量、案例相似度和冲突提示。连续两批不再改字段、关系和去重规则后，才扩大范围。

## 7. 运行时索引派生

知识单元和原始资料完成查重、候选化与校验后，才运行 `scripts/build_runtime_indexes.py`。索引派生过程只读取 frontmatter、`K-20260823-052` 的阶段/方向映射以及 Jackson/Apple Notes 的候选入口：

- `unit-index.json` 只保存身份、状态、主题、触发词和包内路径；
- `route-index.json` 保存任务前路由、状态优先级和最小读取计划；
- `navigation-index.json` 保存任务后单步导航；
- `phrase-route-index.json` 保存候选入口和完整索引的延迟路径，不复制完整话术正文。

生成索引不会改变任何单元的 `status`、`canonical`、`authority` 或 `version`。构建和校验阶段可以读取完整 `manifest.json`，普通聊天首轮不得因索引存在而加载它。
